[STORY 10: Constraint Propagation for Fun]
Story ten. Constraint Propagation for Fun.

[pause]

Constraint propagation is one of those ideas that sounds academic until you watch it solve a real problem in front of you. Eli's post walks through how bicross generates its picross puzzles, and the core technique is beautiful in its simplicity.

Here's the setup. You generate a random grid, calculate the row and column hints from it, then throw the grid away. Now you hand those hints to a solver and ask [pause] can you reconstruct the original grid using only logic? No guessing. No backtracking. Pure deduction.

The solver works by computing every valid arrangement for each row and column, then stacking them up. If a cell is filled in every single valid permutation, it must be filled. If it's empty in every permutation, it must be empty. That's your intersection step. Then you prune [pause] if row zero forces cell three to be filled, go to column three's permutation list and delete any arrangement that doesn't agree. Loop until you converge or get stuck.

What makes this elegant is the acceptance criteria. If the solver gets stuck [pause] if there are cells it can't determine through pure constraint propagation [pause] the puzzle gets rejected. Generate a new one. This guarantees every puzzle a player encounters is solvable without guessing. That's a contract between the game and the player, enforced by math.

Run this forward to game design generally. How many procedurally generated games ask players to make decisions without giving them enough information to reason? Constraint propagation gives you a formal answer to "is this fair?" You generate, you test, you accept or reject. The computational cost is front-loaded at generation time so the player never pays it.

The whole post is open, the technique is well-documented, and the code is right there in the bicross source. Someone building a puzzle game next week can pick this up and use it.
